# Decisions (rebuild 5)

Append-only. Rebuild 4's decisions (OpenReplicant/kernel, `docs/decisions.md`, D-01 to D-93) stay
settled unless an entry here supersedes one. Status: **decided** (owner agreed), **adopted** (taken on
recommendation; confirm or overturn), **proposed** (needs the owner).

| ID | Decision | Status |
| --- | --- | --- |
| R5-01 | **Rebuild 5 keeps the guarantees and changes the boundary.** The claim model, change sets, bitemporality, scopes and invariants carry over (D-01, D-02, D-05, D-09, D-10). The module boundary, the ontology weight and actuation change. See `docs/rebuild-5.md` | decided |
| R5-02 | **The kernel is a blueprint, not a monolith.** Every concern is a slot with an interface and a default provider; nothing has a built-in handler. Even the record store and the write pipeline are slots | decided |
| R5-03 | **Guarantees are a conformance suite.** The invariants are named, executable cases (`kernel/contract/invariants.yaml`). A core-slot provider is valid only if every case passes, and the suite must fail when a check is disabled | decided |
| R5-04 | **No extension code in the commit** (keeps D-86's reasoning). Hook points before the commit may transform, veto or route; after the commit, consumers read the change feed on a cursor and write only by new proposals | decided |
| R5-05 | **Morphogen is the only distribution for now.** Other uses (process intelligence, agent memory) are built with it later. The kernel is built inside the Morphogen repository under `kernel/`, never depending on `morphogen/`, and moves to its own repository when a second distribution needs it | decided |
| R5-06 | **cognee and Graphiti are baselines, not dependencies.** In both, model output becomes the record (Graphiti's LLM dedupes and invalidates on every write, with no switch; neither runs the guarantees). Their approaches are reproduced and scored on our evals; ideas credited in `docs/sources.md` | decided |
| R5-07 | **Actuation through intent.** Approved plans become commits to `morphogen/intent/`; orchestrators reconcile; outcomes are observed, never claimed by the actuator (extends D-53) | adopted — confirm |
| R5-08 | **Lane policy: autonomy level × risk class** (`morphogen/intent/policies/autonomy.yaml`). Irreversible changes always need a person | adopted — confirm |
| R5-09 | **Gates and the stop rule.** G1 contract, G2 self-modifying, G3 someone else's system. No kernel redesign before G1, no Morphogen redesign before G2 | decided |
| R5-10 | **The feed, as-of reads and the no-extension check (T1; the kernel change D-86/D-87(a) allowed).** (a) The feed is its own table, `kernel.feed(seq, change_set, scope)`, written by apply, readable by scope (RLS), so feed readers need no access to `kernel.change_set`, whose ops stay visible only to submitters, validators and reviewers. (b) Numbers come from a one-row counter that apply locks until commit, not from a sequence: with a sequence, a change set that commits later can hold a smaller number, and a cursor already past it skips it for good (the mutant that uses a sequence fails the concurrent-commit case). The cost is that applies serialize from the end of apply to commit. A concurrency failure there (serialization, deadlock, lock timeout) is raised for the caller to retry, never recorded as an invalid change set. Accepted: gaps in a reader's numbers show how many change sets were applied in scopes it cannot read, and when. (c) `api.claims_as_of(valid_at, known_at)` returns claims recorded by `known_at` and true at `valid_at`, with the status and belief recorded by then; redaction holds at every time. Limits, accepted for now: record times are transaction start times, so an answer for a past `known_at` can still change until transactions open at that time have committed (R5-O4); belief is read for the currently active belief model. (d) "No extension code in the commit" is checked on the catalog, over every function reachable from a kernel table: triggers run kernel-owned functions in SQL or PL/pgSQL; defaults, constraints, policies and rules call only kernel or catalog functions; kernel function bodies name no other schema's functions; definer functions pin their search path; no extension owns kernel objects; only the kernel owner can create in the kernel schema. (e) The feed test opens concurrent sessions through `dblink`, installed in the test database only | adopted — confirm |
| R5-11 | **Slot contracts beside the invariants (T2).** (a) A slot with behaviour every provider must match gets a case set in `kernel/contract/slots/<slot>/` (rebuild 4's eval format, ids unchanged); `kernel/contract/run.py` runs, for each provider, the invariant cases if it fills record-store or write-pipeline and the case set of every slot it fills. First sets: validator (13 cases) and belief-model (17), ported from `eval/validator` and `eval/belief-v0`. (b) The providers that first pass them are ported unchanged in logic: validator-shacl (rebuild 4 core and shapes, paths adapted) and belief-corroboration (scoring model); their services come in T3. (c) validator-shacl is the validator slot's default until a JSON Schema provider passes the same set, so G1 has a passing default for every slot with a contract; R5-O1 stays open. (d) Mutants live with each provider (`tests/mutants.py`) and run through `kernel/contract/mutants.py`, which first checks that the unmutated provider passes. The reference-or-premise shape never decides the validator's verdict (the JSON Schema rejects such claims first); it guards exports checked against the shapes alone, so the validator's runner also runs the shape tests, which kill its mutant. (e) The runner fails on a slot the blueprint does not declare, a slot case set with no cases, or no providers; record cases apply to record-store, write-pipeline and change-feed providers | adopted — confirm |
| R5-12 | **Kernel slots Morphogen does not need stay unfilled** (owner, Oct 2026: "If the slot is not necessary for the use case of morphogen leave it blank with a description and explanation"). The slot stays in the blueprint with its interface, `default: none`, `status: unfilled` and a `why` (what it is for, why Morphogen does not need it, when to fill it); nothing depends on an unfilled slot. Today: truth-maintenance (no chains of inferred claims in Morphogen's loop; the belief model's premise cap never applies) and context-assembler (no session briefings; agents query explicitly). Every other kernel slot is in `morphogen/distribution.yaml`'s `uses_kernel_slots` | decided |
| R5-13 | **T3 ports, and how services wake.** (a) `kk.lib` and `kk.changes` come from rebuild 4 into `kernel/src/kk/`; services keep their code shape. (b) Hooks before the commit (the validator) act on submitted change sets, which the feed never carries, so they keep NOTIFY plus a sweep (`listen`). Consumers after the commit (belief, verifier, recall index) `follow` the change feed: they poll `api.feed` after an in-memory cursor (the starting head is read from `kernel.feed`, granted to agents under the same row-level security) and still re-read the record from their own watermark, so nothing is missed while one is down; a durable per-consumer cursor is not needed yet (R5-O5). The recall index also listens on `kernel_redaction` (redactions are not in the feed, R5-O3). Wake rules: belief and the recall index wake on any applied change set, their own included (that step submits nothing and ends the round); the verifier only on change sets that touched claims (rebuild 4: any applied). (c) Ported as Morphogen needs them (R5-12): kernel-mcp's operator tools, not its memory profile or briefing; BM25 recall, not dense fusion or re-ranking. (d) Rebuild 4 gaps fixed on the way, in kernel-mcp: `whoami` failed for every agent that is not a reviewer (it read `api.review_queue` in the same statement; now only when the caller may read it); stdio refused only superusers and `kk_authenticator` by name, and now refuses any login that can create roles, bypass row-level security or act as another agent's role. (e) The SciFact retrieval eval moves to `kernel/evals/scifact` with the abstracts encoded as rebuild 4's paper encoder did (that module stays parked); it is run by hand, not in CI (3 minutes, CC BY-NC data): nDCG@10 0.6606, recall@200 claims 0.9382 against rebuild 4's 0.6594 and 0.9349: a match, not an improvement (here no paper claim has a belief to break ties, and the background corpus is smaller) | adopted — confirm |
| R5-14 | **The self-encoder records structure from files, and the pack loader comes first (T4).** (a) The pack loader is ported (rebuild 4, `packs.sql` identical but for paths): the self-encoder's terms (kk-core, dcterms) must be approved before any of its claims apply. The slot catalog is no longer a pack: the blueprint is. (b) The self-encoder reads `kernel/blueprint/slots.yaml`, every `kernel/providers/*/provider.yaml` and distribution files it is given (the kernel never names a distribution's path). Slots become `kk:Slot` with contract, cardinality and a note (default and status, or why unfilled); providers `kk:fills` their slots; a distribution `dcterms:hasPart` its slots. Every claim cites its file and line (RFC 5147 fragment); a line that cannot be found is an error, never another line's citation. Each change set's key names the file's content and the change set it follows, so the same content again is a no-op while a reverted or restored file is recorded again; a kernel file gone from disk is retracted, a distribution only with `--forget`. The claims go to `urn:kk:scope:vocab` (slot and provider descriptions, as the bootstrap labels it). (c) Providers are not typed `kk:Module` yet: that type needs a module kind and an agent the manifests do not carry, and typing one goes to review; the manifests gain those fields when `module.schema.json` is adapted. Until then `kk:ModuleShape` never runs on them (the validator does no inference from `kk:fills`'s domain), kernel-mcp's `list_modules` does not list them, and nothing links `urn:kk:provider:*` to the `urn:kk:module:*` IRIs runs name; the manifests themselves are reviewed in git. kk-core's `kk:Slot` definition still names rebuild 4's `ontology/slots.yaml` (changing it bumps the pack). (d) `self_encoder answer` is the check: which provider fills each slot, from the self-encoder's own claims only (another agent's `kk:fills` does not count), with claim ids, belief and file:line; a slot not in the record says so | adopted — confirm |

## Open

| ID | Question | Recommendation |
| --- | --- | --- |
| R5-O1 | Keep the RDF/CURIE machinery (prefix table, SHACL in the write path) or move RDF to the edges (export, alignment)? A third of rebuild 4's lessons are prefix, pack and SHACL trouble | Edges: JSON Schema validator by default, SHACL as a candidate validator, N-Quads export kept |
| R5-O2 | Module boundary: Postgres roles reading `api` views (rebuild 4) or protocol contracts (change sets over HTTP, MCP)? | Both: roles stay the identity and clearance mechanism; modules may also submit over HTTP, so any language or harness can be a provider |
| R5-O3 | Redactions are not change sets, so they do not appear in the feed: a projection or index built from the feed keeps redacted content until it re-reads. Number redactions in the same feed (a `kind` column), or keep `pg_notify('kernel_redaction')` as the signal? | Same feed: one cursor covers everything a consumer must react to, and a missed notification cannot leave redacted text in an index |
| R5-O4 | As-of by record time uses transaction start times (`now()`), which do not follow commit order. Add `api.claims_as_of(..., known_through_seq)`, the record as of a feed position, which is repeatable once read? | Yes, when the first consumer needs a repeatable past answer (truth maintenance, evals that replay history); keep `known_at` for people |
| R5-O5 | Feed consumers keep their cursor in memory and re-read from their own watermark on start. Watchers that must react to each change exactly once (T5: anomaly, prediction verifier) will need a durable cursor. Where: a kernel table of consumer cursors (a kernel change), or the consumer's own run records (`finish_run` outputs carry the last seq)? | Run records: no kernel change, and the cursor is then itself recorded and attributed |
