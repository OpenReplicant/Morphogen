## 2026-11-01: v0.2.1, review pass

- **Gap:** a review found ways round the frame:
  - shell writes to locked files with no path in the command (`git apply`,
    scripts) or with `&>`
  - direct commits and ref moves on the trunk
  - `.claude/settings.local.json` or `~/.claude/settings.json` turning hooks off
  - git config and hooks that would run code on the host
  - candidates redefining an existing `cmd:` KPI
  - trial budgets dodged by running the gate from a script
  - `git merge-base` crashing the guard
- **Choice:**
  - The guard snapshots locked files and the trunk before each shell command,
    and undoes changes afterwards (stray trunk commits are kept on
    `rescued/*`).
  - Trunk protection; more deny rules.
  - The gate takes KPI definitions from the base, counts the trial budget
    itself, and has a `--repo` option.
  - Read-only devcontainer mounts for the judge, guard, sandbox and git
    hooks/config.
  - A CI gate workflow for branch protection.
  - Generated map files are no longer committed.
  - A session briefing and a status line for the operator.
- **Why:** each layer is weaker alone. Patterns are cheap, but scripts evade
  them. The snapshot catches what the patterns miss. Read-only mounts protect
  the guard itself, and CI protects the trunk when the agent has shell access.
- **Rung:** generate. These are operator-owned parts.
- **Gate:** not applicable (no Morphogen trunk yet in this repo); scenarios
  tested in a throwaway repo.
